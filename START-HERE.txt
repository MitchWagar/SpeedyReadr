SPEEDY READR — COMPLETE CODE AND UPLOAD DIRECTIONS

This ZIP contains the entire frontend, PDF.js dependency files, and bookmark backend source. It includes the final design with no Restart button. No code has been uploaded to GitHub by ChatGPT.

EASIEST METHOD: UPLOAD THE FILES (desktop browser recommended)

1. Download and extract Speedy-Readr-Complete.zip. Open the extracted folder.
2. Sign into https://github.com/MitchWagar/SpeedyReadr and choose the main branch.
3. Select Add file > Upload files.
4. Drag the CONTENTS of the extracted folder into the upload area. Include the dist, scripts, server, and .openai folders and the root files. Keep the folder structure. Do not upload the ZIP itself or wrap everything in another folder.
5. Include hidden files .nojekyll and .gitignore. On Windows, enable View > Show > Hidden items if necessary. On macOS, press Command+Shift+Period. If .nojekyll cannot be selected, create that file using Add file > Create new file; a comment line is sufficient.
6. Use the commit message "Replace with finished Speedy Readr". Commit directly to main if that option is available. If GitHub requires a pull request, create and merge it.
7. Remove these unused OLD files from the repository: index.js, Dockerfile, and 71aIc+7SyCL._SL1500_.jpg. Open each file, select its menu > Delete file, and commit. The new index.html and package.json replace the old versions. Keep CNAME; the included copy contains speedyreadr.com.
8. Open repository Settings > Pages. Under Build and deployment select Deploy from a branch, then main and /(root), and Save. Keep the existing custom domain speedyreadr.com if already configured. CNAME alone does not configure DNS or a new custom domain.
9. Open the Actions tab and wait for "pages build and deployment" to finish successfully. Open the website using the URL shown in Settings > Pages, then refresh.

The repository ROOT should contain index.html, CNAME, package.json, README.md, START-HERE.txt, .nojekyll, .gitignore, and the dist, scripts, server, and .openai folders. The actual reader is dist/index.html; root index.html opens it automatically. No npm build is required for GitHub Pages.

IF YOU PREFER COPYING AND PASTING

For each text file, open it in a plain-text editor, copy all its contents, and create or edit the matching path on GitHub. For example, use Add file > Create new file and name it dist/app.js to create the folder and file together. Paste the file's contents and commit. Repeat for every file. The PDF modules in dist/vendor are large, so uploading those files is much easier. Their exact filenames and folder locations must be preserved. Do not paste every file into index.html.

BOOKMARKS AND HOSTING

GitHub Pages serves static frontend code. The reader, uploads (DOCX/EPUB/PDF/TXT), italics, speed control, punctuation/dash/paragraph pauses, and percentage controls work there. GitHub Pages cannot run the bookmark backend. The full private app, including your existing saved bookmarks, is still at:
https://still-word-reader.mitchwagar.chatgpt.site

The backend source is supplied in server/worker.mjs. Hosting the full app elsewhere requires an R2 bucket bound as BUCKET and trusted server authentication. Your existing bookmarks and uploaded documents are not included in the code and do not move to GitHub.

To build the full server bundle with Node.js 20 or newer, run npm run build in the extracted folder. There are no npm dependencies to install. See README.md for runtime requirements.

The .openai/hosting.json file identifies the EXISTING private Site; it is not an API key. Do not reuse that project ID for an unrelated new Site. Never add passwords or access tokens to the public repository.
